# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Frontend-specific instructions live in `frontend/AGENTS.md`; read them before changing Expo code.
- Release gates are the CI workflows in `.github/workflows/`: Frontend runs typecheck, lint, the full `npm test` suite (browser suites included) and a web export, each asserting the run left no untracked files behind. Reproduce a red job with the same command it runs, not a local variant.
- **Provider-native Magi Chat is the only human-conversation path.** Chat and Voice use `gateway/app/magi_chat_{api,service,store}.py`, `/api/v1/magi/*`, and `magi_messages` events on `/api/v1/events`; there are no runtime transport flags or selectable worker targets. Historical conversation/Pi tables remain untouched pending an operator-approved migration. See `docs/native-chat-architecture.md`.
- **Reads never own execution lifecycle.** Normal startup and health/runtime/Fleet/agents/Activity/Attention/notification/recent-activity/native-chat reads project persisted objective, `firstmate.execution-event.v1`, and decision rows through `gateway/app/structured_runtime.py`; they must not execute `fm-fleet-snapshot.sh`, scrape Herdr, signal processes, or add a reconciliation timer. Herdr remains only for explicit non-chat snapshot/control seams. See `docs/gateway-runtime-observation-boundary.md`.
- Firstmate captain decisions live in `gateway/app/firstmate_decisions.py`: authenticated complete `firstmate.decision-events.v1` push projections enter the owner-scoped event/store/Attention and `firstmate.decision-context.v1` seams; reads never refresh Firstmate. `firstmate.answer_decision` takes opaque id/revision only, loads exact answer bytes out of band from the owner's canonical Native Chat user row, requires bound confirmation, and invokes pinned `fm-captain-hold.sh` with a private decision file—never terminal/transcript text. See `docs/magi-firstmate-decisions-v1.md`.
- `/api/v1/recent-activity` merges persisted structured objective/execution rows with gh-axi merged PRs; it never runs a Fleet snapshot. See `gateway/app/recent_activity.py` for merge/dedup rules.
- `frontend/src/services/MagiConversationSession.ts` keeps the one owner-scoped Magi thread reactively in memory and persists only principal-qualified canonical and genuine-pending caches. Auth logout/expiry/401/change clears memory and evicts prior-principal keys; Gateway IDs, timestamps, and monotonic revisions remain authoritative. Chat and Voice share this same record.
- Restricted Friend Beta release authority is `docs/friend-beta-release-readiness.md`: operator-issued `mgb_` bearer grants are assigned one-active-per-principal/device (not hardware-bound), digest-only and default to `read,account,notifications`; the CLI requires an explicit shared-runtime acknowledgement for `command`/`voice` and never issues `response`. Native renews through SecureStore, web retains only the short bearer, and online logout/operator revocation retires the grant, sessions, and push registration (offline logout still needs operator revocation). This is not tenant isolation or physical/TestFlight evidence.
- Truthful-state rules are recorded in `docs/truthful-provider-states.md`: a provider is `connected` only with operator OAuth config **and** a stored, unexpired `oauth_credentials` row (`_provider_connection_state` in `gateway/app/main.py`, mirrored fail-closed by `normalizeAuthProvider` in `frontend/src/api/client.ts`); Jira/Teams are deliberately deferred. Uploads carry a server-issued `status: 'stored'`/`attached` and the client refuses to read a bare 200 as success. Never reintroduce a placeholder for an unobserved value — `HerdrClient.get_snapshot`'s old fabricated `version` made `herdr_socket_connected` report true while Herdr was unreachable.
- The chat shell is full-bleed over `EnvironmentBackground`: `src/global.css` gives web one `100dvh` authority and every flex ancestor must preserve `minHeight: 0`; the transcript `ScrollView` is the only chat vertical owner. `app/(tabs)/chat.tsx` measures the floating header/composer and derives transcript insets from their live heights. Drawer and Settings are independent sibling overlays with internal scrollers and pinned controls; the drawer never translates the chat canvas and carries its own close control. Preserve `EdgeScrims` and the shared adaptive glass treatment rather than adding an opaque panel.
- Cosmetic surfaces must not make authorized gateway requests: `authorizedFetch` invalidates the whole session on a 401, so a decoration that 401s signs the operator out. The Magi greeting therefore reads a cached display name (`ACCOUNT_DISPLAY_NAME_KEY`, written by `fetchUserProfile`) through `src/services/Greeting.ts` and stays impersonal until a profile has been observed.
- The drawer and Settings are animated layers over long scrollers, so browser tests must wait for them to arrive and bring controls into view before pressing them.
- Expo's dev server owns `/status`, so the app route of that name is unreachable through `expo start --web`; drive health/telemetry browser tests against `/diagnostics` instead. `frontend/src/components/WorkspaceShell.tsx` is currently unreferenced by any route.
