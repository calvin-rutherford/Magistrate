# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Frontend-specific instructions live in `frontend/AGENTS.md`; read them before changing Expo code.
- Release gates are the CI workflows in `.github/workflows/`: Frontend runs typecheck, lint, the full `npm test` suite (browser suites included) and a web export, each asserting the run left no untracked files behind. Reproduce a red job with the same command it runs, not a local variant.
- **The terminal is not the chat database.** `gateway/app/conversation_store.py` is the canonical record for captain conversation: `/api/v1/captain/prompt` creates one turn keyed by the client's `message_id`, and terminal snapshots are an *adapter* that upserts that turn's reply and tool events into fixed slots. `/api/v1/conversations/{target}/messages` and the `conversation_messages` WebSocket event are the only captain transcript sources; the client contract is append-or-update by canonical id (`frontend/src/services/CanonicalConversation.ts`). Captain routing resolves Herdr's explicitly labelled `firstmate`/`captain` workspace and must never fall back to an arbitrary known-harness worker. Read `CHAT_ARCHITECTURE_FIX.md` before touching any chat delivery path.
- Herdr exposes no conversation API; agent chat history is parsed from terminal snapshots by `parse_agent_history` in `gateway/app/herdr_client.py` (see its docstring for marker conventions), mirrored in `frontend/src/services/ChatHistory.ts` — keep the parsers in sync, including `classify_history_rows`/`sanitizeTerminalHistory` and `tool_call_preview`/`toolCallPreview`. Pi role boundaries survive only in ANSI background boxes, so Gateway history reads ANSI; markerless plain-text fallback fails closed rather than exposing harness rows. A working agent's snapshot can be transiently empty (alternate screen/redraw), so consumers must tolerate empty output. Claude can push a growing reply's prompt off that viewport; canonical ingestion may continue a promptless leading segment only on substantial prose overlap with exactly one previously attributed turn (`_has_reply_continuity`), never by choosing the latest open turn.
- Tool-call visibility in chat history uses the single persisted key `magistrate.chat.show-tool-calls` (`frontend/src/services/ChatPreferences.ts`); do not introduce a second key.
- Claude's harness renders tool activity as *unmarked* rows set off by a blank line, and herdr snapshots catch status overlays mid-frame (sometimes overwriting a message row) — both parsers must drop chrome and type tool rows, or tool output leaks into chat as prose. Verify parser changes against a real snapshot (`HerdrClient.read_agent_output`), not only fixtures.
- A snapshot carries no audience field, so an unrecognised row must fail closed, never default to `role: 'user'`. Real leak classes both parsers now exclude or retype: Pi tool envelopes boxed like user turns, Firstmate control plumbing, harness overlays (`/usage` tab bars and block meters), and the `───`-framed composer — Herdr catches that composer mid-keystroke, so treating it as a turn minted one "user message" per character. Excluded rows become `kind: 'control'`: never rendered, but still the audience boundary they occupied (a *user*-role control row closes a captain turn; agent-role ones are interleaved noise).
- Herdr exposes no durable message ids, so `get_agent_history` hashes row content — and that content grows, reflows, and scrolls while a reply renders, giving one logical row many ids. That is why captain chat no longer uses it. It remains the **worker-pane** transcript (those panes include autonomous and Firstmate turns with no Magistrate submission id), where `frontend/src/services/ChatIdentity.ts` still supplies identity and revision matching; those paths are marked `TRANSITIONAL` in `app/(tabs)/chat.tsx`. Never reintroduce them for the captain target.
- `gateway/app/firstmate_client.py` reads the live `fm-fleet-snapshot.sh --json` schema. Captain-attention signal lives at `task.hints.pending_decision` / `hints.blocked_event`, with keyed decisions in `hints.open_decisions`; join task ids against `snapshot.backlog.records` for titles. Fleet agent display names join Herdr pane ids to `task.endpoint.target` via `apply_agent_display_names`, preferring Firstmate's task title and falling back to Herdr identity.
- `/api/v1/recent-activity` merges two real sources: fleet-snapshot task records (`backlog.records` + `secondmate_landed.records`, request/completion dates are date-only) and gh-axi merged PRs (relative timestamps like `2h ago`, normalized in `gateway/app/github_service.py`). See `gateway/app/recent_activity.py` for the merge/dedup rules.
- `frontend/src/services/ConversationSession.ts` keeps normalized messages reactively in memory. Captain startup restores the strictly validated canonical cache (`magistrate.chat.canonical.v1.captain`, keyed by canonical id) plus genuine unacknowledged sends (`magistrate.chat.pending.v1.captain`, keyed by `client_message_id`) before fetching Gateway; success authoritatively prunes/replaces the snapshot, while a transient failure leaves it visible with a stale state. The cache never becomes authority, and terminal-era v1/v2 arrays are deleted, not migrated. Gateway timestamps and monotonic revisions still win. Attachment rows contain bounded metadata/authenticated references only; bytes stay in `app/uploads.py`. Worker targets retain transitional v2 storage; Chat and Voice share the canonical `'captain'` record.
- Truthful-state rules are recorded in `docs/truthful-provider-states.md`: a provider is `connected` only with operator OAuth config **and** a stored, unexpired `oauth_credentials` row (`_provider_connection_state` in `gateway/app/main.py`, mirrored fail-closed by `normalizeAuthProvider` in `frontend/src/api/client.ts`); Jira/Teams are deliberately deferred. Uploads carry a server-issued `status: 'stored'`/`attached` and the client refuses to read a bare 200 as success. Never reintroduce a placeholder for an unobserved value — `HerdrClient.get_snapshot`'s old fabricated `version` made `herdr_socket_connected` report true while Herdr was unreachable.
- The chat shell is full-bleed over `EnvironmentBackground`: `src/global.css` gives web one `100dvh` authority and every flex ancestor must preserve `minHeight: 0`; the transcript `ScrollView` is the only chat vertical owner. `app/(tabs)/chat.tsx` measures the floating header/composer and derives transcript insets from their live heights. Drawer and Settings are independent sibling overlays with internal scrollers and pinned controls; the drawer never translates the chat canvas and carries its own close control. Preserve `EdgeScrims` and the shared adaptive glass treatment rather than adding an opaque panel.
- Cosmetic surfaces must not make authorized gateway requests: `authorizedFetch` invalidates the whole session on a 401, so a decoration that 401s signs the operator out. The Magi greeting therefore reads a cached display name (`ACCOUNT_DISPLAY_NAME_KEY`, written by `fetchUserProfile`) through `src/services/Greeting.ts` and stays impersonal until a profile has been observed.
- The drawer and Settings are animated layers over long scrollers, so browser tests must wait for them to arrive and bring a control into view before pressing it — use `openSettingsSheet`/`clickInSheet` in `tests/chat-terminal.web.test.js`. A bare click issued mid-animation fails as "Node is either not clickable".
- Expo's dev server owns `/status`, so the app route of that name is unreachable through `expo start --web`; drive health/telemetry browser tests against `/diagnostics` instead. `frontend/src/components/WorkspaceShell.tsx` is currently unreferenced by any route.
